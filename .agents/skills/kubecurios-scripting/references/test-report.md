# `kjs/test.md` 验收报告模板

将下面模板填写成与交付脚本同级的 `kjs/test.md`，不要原样复制占位符或在技能目录产生实测报告。交付时先建档，测试后在同一份报告中更新。每个适用项单列，复杂功能按物品、触发条件和观察视角拆开。

结果只用「通过」「失败」「未测」「阻塞」「不适用」。验收层级标为「静态」「自动回归」「专用服」「真实客户端」「用户反馈」，不要用一种替代另一种。通过要有与当前交付版本对应的实际证据；用户说没测、没看到或未回应，不能推定通过。使用用户反馈时明确归因，勿称 agent 亲眼看到。复测后保留先前失败的条件及修复版本，给出新结果。

证据用交付相对路径、日志文件名和行号／关键行、脱敏截图、实际观察数值或用户确认；命令中的私人绝对路径用 `<测试目录>` 等代称。不要贴账号、UUID、令牌、私人服务器地址或原始启动参数、日志。若证据不随包交付，标明如何复现，而不是给出失效的本机链接。
