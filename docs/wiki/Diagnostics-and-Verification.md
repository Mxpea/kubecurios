# 排错、测试与重连兼容

[返回首页](Home.md)

## 物品放不进槽位

先确认物品能通过 `/give` 获取，再看服务端 `logs/latest.log`。KubeCurios 在服务器启动且 Curios 槽位数据已加载后检查白名单。

| 启动日志 | 检查方法 |
|---|---|
| `whitelist item ... is not registered` | 核对完整物品 ID 和注册脚本是否加载。 |
| `slot ... is not defined` | 核对数据包是否启用，以及 `curios/slots/` 下的文件名是否与脚本槽位 ID 一致。 |
| `does not reference validator` | 在槽位的 `validators` 中加入 `kubecurios:whitelist`。 |
| `is not assigned to any entity` | 在槽位文件或实体分配文件中给目标实体分配该槽位。 |
| `assigned to other entities only` | 这条信息表示只有非玩家实体拥有该槽位。要给玩家使用，需将槽位分配给 `minecraft:player`。 |
| `starts with zero slots for players` | 玩家初始格数为 0。检查槽位 `size` 和整合包的槽位配置。 |

物品能装备但属性没有变化时，确认放的是功能格、装备者拥有该属性实例，并核对[属性 ID 和运算名](Scripting-API.md#属性-id-和运算方式)。

## 已验证的行为

- 当前专用开发服自动回归用测试实体验证了生命上限固定加法 `20 → 24 → 28 → 24 → 20`、两个格子的装备与卸下回调、槽位查询、已有紫水晶碎片进入白名单及白名单外石头被拒绝。测试也核对了未知物品、未知槽位、缺少验证器和未分配实体的日志。
- 战斗回归验证了命令能以佩戴者或攻击者为执行者及定位基准，冷却期间取下重戴无法重触发。数值检查覆盖正负受伤与输出倍率、火焰标签和摔落伤害类型、护甲与韧性。提示检查覆盖红蓝颜色、`hideAttribute()` 和手写物品描述保留。
- 脚本效果回归覆盖半血增伤、条件护甲、每 5/20 tick 回调、命令真假与真实嵌套队列。客户端重连也通过验收，两枚同款戒指的原生护甲与临时护甲在重连前后都稳定为 `2 + 4`。
- 装备脚本回归覆盖命令整数（零、负数、多结果冲突和排队）、标签计数、同款来源格切换、累计佩戴时间、耐久消耗与破碎清理。累计时间测试核对双戴只计一次、卸下或停用以及破碎后的空档不计时、实体存档读回后继续累计。耐久附魔用固定随机种子比对原版减耗。此前的联机验收确认了原版跳跃和拾取统计的增量，以及重连后耐久仍为 `32/128`。
- 此前用开发客户端手动验收了真实玩家的穿脱，并确认断开后重新连接同一台服务器时，两枚戒指和 28 点生命上限均保留。
- 客户端外观验收确认：守卫戒指显示金头盔，血誓戒指显示胸前挂件；戴上真正的钻石头盔后只显示钻石头盔和挂件，卸下两枚戒指后对应外观消失。专用服回归确认外观配置未给实际物品添加原版 `EQUIPPABLE` 组件。
- `add_multiplied_base`、`add_multiplied_total` 和生命上限以外的属性已通过同一个 Curios 属性接口接入，当前回归没有逐项断言这些数值。

源码工作区可运行 `runAttributeSmoke` 重现自动验证。任务会在 `build/attribute-smoke/run` 中运行专用开发服并在测试结束后停服。构建命令见 [README](../../README.md#编译和自动验证)。

## 重连后当前血量变为 20

玩家断开后重新连接同一台仍在运行的服务器时，Minecraft 会重新加载玩家数据。当前血量先被当时的上限裁剪，Curios 稍后才重新应用饰品的临时属性。在对照测试里，移除 KubeCurios 后，用带 Curios 原生加成的紫水晶碎片仍能复现这个加载顺序。保存时为 `28/28`，加载时为 `20/20`，Curios 应用属性后变为 `20/28`。

在专用服加入 **Max Health Fix 1.2** 可以恢复退出前的当前血量。以下是只在测试服务器安装修复模组时的真实客户端重连结果。

| 退出前 | 重连后稳定值 | 装备状态 |
|---|---|---|
| 满血 `28/28` | `28/28` | 两枚戒指保留 |
| 受伤 `23/28` | `23/28` | 两枚戒指保留 |

登录事件仍可能短暂读到 `20/20`，随后几 tick 内恢复。这项修复可以作为整合包的可选依赖。 [Max Health Fix](https://modrinth.com/mod/MaxHealthFix)
